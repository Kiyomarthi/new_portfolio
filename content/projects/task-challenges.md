# چالش اصلی

::warning
**وضعیت پروژه:** وبسایت این پروژه دیگر در دسترس نیست و شما به پروتوتایپ آن متصل می شوید.
::

**پروژه مدیریت وظایف ویاناسیستم** یک سیستم مدیریت پروژه و Task Management بود که با هدف مدیریت بهتر وظایف، پروژه‌ها و فعالیت‌های تیمی توسعه داده شد.

ساختار کلی این پروژه از ابزارهایی مانند Trello الهام گرفته بود و تمرکز آن روی ایجاد یک محیط منعطف برای مدیریت وظایف و مشاهده وضعیت پروژه‌ها از طریق نماهای مختلف بود.

## مدیریت وظایف

یکی از بخش‌های اصلی پروژه، پیاده‌سازی سیستم مدیریت Taskها بود.

کاربر می‌توانست وظایف مختلف را ایجاد و مدیریت کند و وضعیت آن‌ها را در ساختار پروژه مشاهده کند.

اطلاعات مربوط به هر Task به شکلی نمایش داده می‌شد که کاربر بتواند وضعیت کلی فعالیت‌ها و پیشرفت پروژه را به‌سادگی دنبال کند.

## نماهای مختلف

یکی از چالش‌های اصلی پروژه، ارائه یک داده یکسان در قالب **Viewهای مختلف** بود.

برای این منظور چند نوع نمایش برای مدیریت وظایف پیاده‌سازی شد.

### نمای Kanban

در نمای Kanban، وظایف بر اساس وضعیت خود در ستون‌های مختلف قرار می‌گرفتند.

این ساختار امکان مشاهده سریع وضعیت وظایف و جابه‌جایی آن‌ها میان مراحل مختلف را فراهم می‌کرد.

### نمای Card

در نمای Card، اطلاعات وظایف به صورت کارت‌های مستقل نمایش داده می‌شد.

این مدل نمایش برای مشاهده جزئیات Taskها و مدیریت آن‌ها در قالبی ساده و بصری طراحی شده بود.

### نمای Timeline

یکی دیگر از نماهای پروژه، **Timeline** بود.

در این نما وظایف و فعالیت‌ها بر اساس زمان نمایش داده می‌شدند و کاربر می‌توانست ارتباط میان فعالیت‌ها و بازه زمانی انجام آن‌ها را مشاهده کند.

پیاده‌سازی این View نیازمند مدیریت صحیح اطلاعات زمانی و تبدیل داده‌های Task به یک ساختار قابل نمایش روی Timeline بود.

## مدیریت جابه‌جایی وظایف

یکی از قابلیت‌های مهم پروژه، امکان جابه‌جایی و مدیریت بصری Taskها بود.

این قابلیت باعث می‌شد کاربر بتواند بدون انجام عملیات پیچیده، وضعیت و ترتیب وظایف را از طریق رابط کاربری مدیریت کند.

در این بخش با مفهوم **Drag & Drop و مدیریت State پس از جابه‌جایی عناصر** نیز کار شد.

## طراحی UI و UX

با توجه به ماهیت پروژه، رابط کاربری نقش مهمی در تجربه استفاده از سیستم داشت.

هدف این بود که کاربر بتواند تعداد زیادی Task و اطلاعات پروژه را بدون پیچیدگی بصری مدیریت کند.

برای همین مواردی مانند:

- Hierarchy اطلاعات
- نمایش وضعیت Taskها
- دسته‌بندی وظایف
- فاصله‌گذاری و Layout
- تعاملات Drag & Drop
- تغییر View
- نمایش اطلاعات زمانی
- Responsive بودن صفحات

در طراحی و توسعه مورد توجه قرار گرفتند.

## معماری قابل توسعه

از آنجا که یک Task می‌توانست در Viewهای مختلف نمایش داده شود، ساختار پروژه به شکلی طراحی شد که داده‌های اصلی از نحوه نمایش آن‌ها تا حد امکان مستقل باشند.

به این ترتیب یک Task می‌توانست بدون ایجاد داده‌های تکراری در نماهای مختلف مانند Kanban، Card و Timeline نمایش داده شود.

این رویکرد باعث شد اضافه کردن Viewهای جدید یا تغییر نحوه نمایش اطلاعات در آینده ساده‌تر باشد.

## استفاده از Tailwind CSS

در این پروژه برخلاف برخی پروژه‌های قبلی، برای طراحی رابط کاربری از **Tailwind CSS** استفاده شد.

استفاده از Utility Classها امکان پیاده‌سازی سریع Layoutها و کنترل دقیق جزئیات ظاهری را فراهم کرد.

همچنین از ابزارهایی مانند `tailwind-merge` برای مدیریت و ترکیب کلاس‌های Tailwind استفاده شد.

## نتیجه

پروژه Task Manager ویاناسیستم تجربه‌ای عملی در زمینه طراحی و توسعه یک ابزار مدیریت پروژه و وظایف بود.

مهم‌ترین بخش‌های این پروژه شامل پیاده‌سازی **Kanban، Card View، Timeline، Drag & Drop و مدیریت State وظایف** بود.

همچنین این پروژه تجربه خوبی در زمینه طراحی رابط‌هایی بود که باید حجم زیادی از اطلاعات را به شکل ساده و قابل فهم نمایش دهند.

در این پروژه با استفاده از **Nuxt.js، Vue.js، Pinia و Tailwind CSS** ساختاری برای مدیریت وظایف ایجاد شد که قابلیت توسعه و اضافه شدن Viewهای جدید را نیز داشته باشد.
